# Release baseline: windows-dev

Machine: see bench/baseline/MACHINE.md. Python 3.12, JMH 1.37 on Oracle HotSpot 22.0.2+9-70. Measured on 2026-10-18.
Native libraries built from commit 5927971 (main) with three toolchains:

| Name | Toolchain |
|---|---|
| ce22 | GraalVM Community Edition 22.0.2+9.1 |
| ce25 | GraalVM Community Edition 25.0.2+10.1 (the toolchain of the wheels, D224) |
| ora25 | Oracle GraalVM 25.0.4+7.1 |

## Toolchains compared

native_ratio.py runs the same Java probe in the JVM and inside the native library, three alternating rounds:

    python python/benchmarks/native_ratio.py --library <dll> --limit 1000

| Toolchain | add_edge, native ns/op (rounds) | has_edge, native ns/op (rounds) | add_edge ratio to the JVM |
|---|---|---|---|
| ce22 | 6,706 / 6,993 / 6,387 | 693 / 746 / 671 | 12.10 / 12.33 / 11.03 |
| ce25 | 6,636 / 6,605 / 6,617 | 690 / 696 / 683 | 11.44 / 11.53 / 12.60 |
| ora25 | 4,371 / 4,587 / 4,290 | 447 / 471 / 425 | 8.03 / 8.22 / 7.32 |

The medians of ce25 and ce22 are 1.3% apart on add_edge and 0.4% apart on has_edge, inside D224's 10% rule. Oracle
GraalVM took about a third less time per call. CI measured ratios on Oracle GraalVM 25 of 6.14 and 7.96 (Windows)
and 2.87 and 8.18 (macOS) in run 39051369528; the Community Edition ratios on CI are set by the first CI run of the
release branch.

## The code behind the README's first table, against the release code

Commit 0b05475 (2026-10-03, the commit that recorded the original table) was built with ce22 and run with its own
compare.py, alternating with the release code built with ce22, on 2026-10-18:

| Code | flat inserts/s | batch inserts/s | single inserts/s | 3-hop median |
|---|---|---|---|---|
| 0b05475 | 1,301,428 / 1,056,179 | 562,414 / 548,896 | 215,027 / 214,664 | 10.7 / 10.3 us |
| release code | 169,954 / 167,184 | 139,983 / 143,653 | 75,587 / 72,816 | 26.5 / 27.3 us |

The old numbers reproduce on this laptop today, so the difference is in the code: 6.5 to 8 times on flat inserts and
about 2.6 times on the 3-hop median. The cause has not been investigated.

## CE 25.0.1, measured on 2026-10-20 (D241)

GraalVM CE 25.0.2 has no macOS Intel build, so the Intel wheel uses CE 25.0.1. Ten alternating rounds of
native_ratio.py on the same laptop, native ns/op, medians (the machine was slower than on 2026-10-18):

| Toolchain | add_edge | has_edge | against ce22 |
|---|---|---|---|
| ce22 (22.0.2) | 7,022 (min 6,631, max 7,386) | 720 (min 662, max 749) | |
| ce25 (25.0.2), 7 rounds | 7,240 (min 6,990, max 8,198) | 752 (min 700, max 780) | +3.1% and +4.5% |
| ce2501 (25.0.1) | 7,341 (min 6,775, max 8,398) | 794 (min 733, max 973) | +4.6% and +10.4% |

CE 25.0.1 is 0.4 points over D224's 10% line on has_edge, inside the round-to-round spread of the baseline itself
(ce22 has_edge ranges 662 to 749). compare.py with only the NodusDB backend, two rounds each:

| Toolchain | flat inserts/s | 3-hop median |
|---|---|---|
| ce22 | 150,892 / 139,829 | 26.8 / 26.4 us |
| ce2501 | 136,303 / 152,020 | 44.0 / 29.7 us |

Library size of ce2501: 39,084,032 bytes. The full table for ce2501 (one run): flat 149,674 inserts/s, 119,129
deletes/s, 36.3 us 3-hop; batch 125,816 and 109,051, 28.0 us; single 68,140 and 61,225, 27.6 us; networkx single
136,678 and 260,822, 36.5 us; networkx batch 111,109 and 248,606, 34.7 us; sqlite3 single 89,964 and 100,349,
115.2 us; sqlite3 batch 119,701 and 117,563, 139.2 us. Inserts on 2026-10-20 ran about 10% below 2026-10-18 for every
toolchain, as the README warns for this laptop.
